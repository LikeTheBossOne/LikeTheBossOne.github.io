A world built on systems

BossCraft brings together the parts of engine development I enjoy most: generating a world, getting it onto the screen efficiently, and keeping it responsive across multiple players. I built a component-based networking structure around an entity-component-system architecture.

Meshing & rendering

The world is divided into 16 × 16 × 16 block chunks. When a block changes, only its chunk and any affected neighboring chunks need their meshes rebuilt.

Mesh generation skips faces hidden by neighboring opaque blocks. Triangle data is packed into integers before it reaches the GPU, where the shader unpacks it for rendering. Both choices reduce the work needed to represent a dense voxel world.

Keeping the render thread moving

Chunk generation and meshing can be expensive. I built a job system that queues work on background threads, then places completed results into a thread-safe queue. The main thread picks up those results for rendering.

This separates world-building work from frame rendering, so loading a chunk does not require doing all of its computation on the render thread.

Making multiplayer feel responsive

RakNet handles low-level networking, while BossCraft’s own systems decide which state to send between the authoritative server and its clients.

  • Client interpolation smooths entity movement between received states.
  • Input buffering helps clients adapt to state changes dictated by the server.
  • Chunk synchronization supports client requests and server-driven updates when another player changes the world.
  • Run-length encoding compresses chunk data before transmission.
  • A thread-safe outgoing queue coordinates network messages produced by background work.
